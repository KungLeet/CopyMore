# CopyMore 局域网协议 v2

## 连接和信任

- 电脑发布 DNS-SD `_copymore._tcp`，实例名 `CopyMore-<server UUID>`，端口可随启动改变。
- 传输使用 TLS 1.2+。Mac 首次运行生成自签名证书与稳定 UUID；私密身份和配对令牌保存在当前用户的 CopyMore 本地文件（目录 0700 / 文件 0600）；TLS 身份仅导入内存，不使用钥匙串。
- 手机扫码得到 `copymore://pair?v=2&id=…&name=…&host=…&port=…&fp=…&key=…`。`fp` 是叶证书 DER 的 SHA-256 小写十六进制；`key` 是 32 字节随机值的 Base64。
- URL 参数采用 RFC3986 百分号编码，`+` 是 Base64 的实际字符，不是空格。
- 手机建立 TLS 时先验证证书有效期和扫码获得的指纹，再发送任何密钥。不得把“信任任意证书”当作生产实现。
- 票据 10 分钟有效，成功配对一次后销毁。新设备需在 Mac 重新生成二维码。最多 8 个并发连接；未认证连接 12 秒内必须完成握手。
- 认证拒绝全局限速为每分钟 12 次。令牌为 32 字节随机值。Android 用 Keystore 的 AES-GCM 密钥加密配对信息，并禁用系统备份。

## 消息

TLS 字节流中每条消息是一行 UTF-8 JSON，以 LF 结尾。不要依赖 TCP 接收边界。所有 ID 为 UUID。

首次手机发送：

```json
{"type":"pair","version":2,"deviceId":"UUID","name":"我的手机","secret":"Base64"}
```

电脑返回 `{"type":"paired","token":"Base64","serverId":"UUID","name":"Mac 名称"}`。随后即可传输内容。再次连接发送 `{"type":"auth","version":2,"deviceId":"UUID","token":"Base64"}`，成功返回 `{"type":"ready","serverId":"UUID","name":"Mac 名称"}`。

拒绝返回 `{"type":"error","reason":"not_paired"}` 等原因后断开。手机每 15 秒发送 `{"type":"ping"}`，电脑回复 `{"type":"pong"}`。手机超时后使用退避重试，重新发现端口和地址，始终校验原有证书身份。

## 电脑到手机

文字消息：

```json
{"type":"clipboard","id":"UUID","kind":"text","text":"内容","created":1790000000.0}
```

解码后的文字 UTF-8 最多 256 KiB。Mac 忽略剪贴板中标为 Concealed / Transient / AutoGenerated 的内容；复制配对链接时也标记 Concealed，避免自动外发。

附件先发布轻量下载卡片，不主动传输文件数据：

```json
{"type":"attachment_offer","id":"UUID","kind":"file","name":"例子.pdf","mime":"application/pdf","size":12345}
```

手机对图片和 8 MiB 以内文件自动请求下载；大文件由用户点击下载。请求发送 `{"type":"download","id":"UUID"}`。电脑只接受已认证设备对本次运行内最近 20 条复制记录中的文件 ID 的请求，不能指定任意文件路径。下载消息顺序为：

```json
{"type":"transfer_start","id":"UUID","kind":"file","name":"例子.pdf","mime":"application/pdf","size":12345}
{"type":"transfer_chunk","id":"UUID","data":"Base64"}
{"type":"transfer_end","id":"UUID","sha256":"64位小写hex"}
```

`kind` 为 `file` 或 `image`。没有固定的 25 MiB 文件上限；`size` 使用非负 64 位整数。每块二进制最大 48 KiB，SHA-256 边传输边计算，在结束消息提供。电脑只保留文件引用和大小/文件身份/修改时间；每次下载打开源文件时及结束时校验文件状态。原文件改变或无法读取则失败，不把新内容伪装为旧卡片的内容。

手机只接受已发出请求 ID 对应的传输，开始时核对卡片中的大小和类型，校验剩余磁盘空间（保留 16 MiB 余量），边接收边写入私有临时文件。累计字节数不可超过声明长度；结束时校验长度和 SHA-256，再改为完成文件。接收端以 UUID 命名文件，原文件名仅用于展示；不得使用传入文件名拼接路径。

每个手机同时下载一个文件。`{"type":"cancel_download","id":"UUID"}` 取消当前传输，电脑回复 `{"type":"download_cancelled","id":"UUID"}`。失败或源文件过期回复 `{"type":"download_error","id":"UUID","reason":"可展示的原因"}`。取消/断开/校验失败会删除临时文件，重试从零开始。下载过程中仍可同步新的文字和附件卡片。

成功落盘或接收文字后，手机返回 `{"type":"received","id":"UUID"}`；接收失败返回 `{"type":"transfer_error","id":"UUID"}`（连接仍可写时）。**received 只表示已接收，不表示粘贴成功。** 文字和已下载附件自动尝试写入剪贴板；图片和文件采用 content URI、真实 MIME 与系统临时读取授权，另保留手动复制、分享和另存入口。接收端剪贴板描述添加来源标记，自动反向读取时跳过。

Mac 未认证接收帧上限 16 KiB，认证后上限 2 MiB（同时对各字段和 48 KiB 分块单独校验）；Android 接收帧上限 2 MiB（覆盖转义后的文字）。Android 保留最近 20 条记录，正在下载的卡片暂时保留；不再设置 100 MiB 总量限制。历史清理只删除应用内附件，不删除用户通过系统另存的文件。未下载的卡片和已下载文件状态持久保存，重新连上相同 Mac 后可请求尚未过期的记录。

v2 与 v1 的附件语义不兼容，两端需要一起升级。TLS 身份与配对令牌不随协议版本更换。

## 图片预览

`attachment_offer` 可包含 `thumbnail`：JPEG 缩略图的 Base64，原始数据最多 96 KiB，最长边 480 像素。Android 限制编码长度和解码尺寸；下载完成仍保留缩略图，并优先显示本地图片。原图始终通过原有分块流程传输。

## 手机到电脑（0.4 新增）

`paired` / `ready` 增加 `features: ["push-v1", "thumbnail-v1"]`。手机只向宣告 `push-v1` 的 Mac 发送新消息，避免旧版误解析。配对版本仍为 v2，不需要重配对。

文字发送 `{"type":"push_text","id":"UUID","text":"内容"}`，上限 256 KiB。文件发送 `push_begin`（包含 id、kind、name、mime、size），收到同 ID 的 `push_ready` 后，发送 `push_chunk`（id、data，48 KiB）及 `push_end`（id、sha256）。服务器写入当前用户专属目录，规范化文件名、检查磁盘余量和累计长度；仅完整校验后写入 Mac 系统剪贴板。图片同时提供文件 URL 和可支持的图像表示。每个连接只接收一个上传，认证、暂停和撤销配对仍生效。

完成返回 `push_received`；失败返回 `push_error`（id、reason）并清理未完成文件。`push_cancel` 清理正在接收的上传。断线时取消发送并清理手机临时源文件，需要用户重新复制/分享重试，不在后台无限重发。完成文件由 Mac 最近 20 条记录持有；记录淘汰后删除本应用接收缓存。

Mac 更新剪贴板时同步更新监视计数，不将手机刚发来的内容回传给同一手机；Android 自动读取跳过来自 Mac 的来源标记、自己的文件 URI、敏感标记和配对链接，并用内容摘要去重。系统分享为用户主动发送，不读取其他内容。Android 10+ 普通应用只能在获得焦点时读取剪贴板，因此支持返回 CopyMore 自动发送，及系统 ACTION_SEND 分享入口；不宣称后台可持续监听其他应用的复制。

## 尚未覆盖

断点续传、文件夹、多文件批量、冲突解决、跨公网中转及多电脑同时连接。Mac 可信任多台手机；Android 当前一次保存一台 Mac。
