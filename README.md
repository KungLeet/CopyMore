# CopyMore

电脑复制，手机使用。面向 macOS、Windows、iOS 和 Android 的原生剪贴板共享产品。

## 已确认的产品约束

- 电脑与手机分别安装独立应用。
- 正式客户端采用原生 UI 与系统接口，不使用 Electron、WebView、PWA 或浏览器套壳。
- 两台设备在同一 Wi-Fi / 可互通的局域网内首次配对，之后保存设备身份并自动重连。
- 短暂断网、地址变化或设备休眠不清除配对。取消配对是单独的明确操作。
- 操作越简单越好：电脑常驻托盘，默认自动同步；手机首页优先展示最新内容，历史与设置放在次级入口。
- 支持文字、图片与文件。文件在手机端提供保存或系统分享，不把文件接收等同于所有应用都能粘贴文件。

## 原生客户端方案

| 平台 | 原生界面 | 核心职责 |
| --- | --- | --- |
| macOS | Swift / SwiftUI，必要时 AppKit | 菜单栏应用、剪贴板变化、文件访问、局域网服务 |
| Windows | C# / WinUI 3，必要时 Win32 | 系统托盘、剪贴板变化、文件访问、局域网服务 |
| iOS | Swift / SwiftUI，必要时 UIKit | 设备发现、接收、复制、保存与系统分享 |
| Android | Kotlin / Jetpack Compose | 设备发现、接收、剪贴板与文件、平台允许的后台连接 |

各端共享协议、内容类型与交互规则；分别实现原生系统能力。macOS 与 Android 已开始实现，当前为 0.4 原生开发预览版；Windows 与 iOS 尚未开发。

## 连接与同步设计

1. 首次：两端安装并打开 → 连接同一 Wi-Fi → 允许局域网访问 → 配对确认一次。
2. 日常：启动客户端 → 自动发现已配对设备 → 校验已保存的设备身份 → 建立连接。
3. 电脑复制：检测内容 → 按内容类型发送 → 手机接收并显示可用操作。
4. 暂时离线：保留配对和已接收内容，显示等待上线；网络恢复且客户端可运行时自动重连。
5. 明确取消配对：删除信任关系，再次连接需要重新确认。

首次版本采用局域网直连，不要求账户或云端中转。已实现 mDNS/DNS-SD 发现、TLS 加密、二维码绑定证书指纹、一次性配对密钥与持久设备令牌。信任绑定稳定设备身份，不绑定易变化的 IP 地址。二维码有效期为 10 分钟，成功使用一次后失效。

## 必须纳入实现验收的平台差异

自动重连的前提是设备网络可互通、应用获准访问局域网，并有运行机会。相同 Wi-Fi 名称本身不能保证访客网络中的设备互通。

- iOS 首次局域网访问需系统授权。后台执行时间受系统管理，因此保证“打开 App 后自动发现和重连”；锁屏或被挂起期间持续同步需要真机验证，不能承诺永远在线。
- Android 的剪贴板读取与后台执行同样有平台限制。电脑到手机的接收、手机到电脑的后台读取须分别验证，不能当作同一能力。
- 接收成功、写入系统剪贴板、文件落盘是三个独立状态。UI 必须准确反映实际结果。

## 当前交付状态

### macOS + Android 原生开发预览版

- `native/macos/`：SwiftUI 菜单栏与窗口、系统剪贴板检测、连接二维码、自动发送、暂停、重新发送、设备撤销、登录时启动入口。身份与令牌存入仅当前用户可访问的应用本地文件，TLS 身份只在内存中使用（macOS 15+）。
- `native/android/`：Kotlin / Jetpack Compose、原生扫码、局域网发现、后台连接通知、断线重试、系统剪贴板写入、原生分享/保存、图片预览、最近接收与配对管理。配对信息使用 Android Keystore 加密。
- 当前数据方向为 **Mac ↔ Android**。文字上限 256 KiB。图片和文件先同步名称/大小；图片与不超过 8 MiB 的文件自动下载并写入手机剪贴板，更大的文件点击下载后自动复制；已移除 25 MiB 文件上限，实际受手机可用存储空间限制。暂不支持文件夹和一次复制多个文件。
- 手机保留最近 20 条内容，已移除 100 MiB 历史总量限制以支持大文件；下载存储在应用内部，可通过“另存为”长期保留。清空记录会删除应用内附件；保存到其他位置的文件不受影响。
- 普通文字收到后尝试自动写入手机系统剪贴板。图片/文件下载后自动复制为带权限的内容 URI；目标应用必须支持粘贴该类型，否则使用分享或保存。
- 断开网络、电脑休眠、应用重启保留配对。Mac 需要运行，Android 需要获准运行后台服务；被强行停止后需重新打开应用。
- `build/CopyMore-macOS.zip` 与 `build/CopyMore-Android.apk` 为本地开发包，非商店发布包。Mac 包针对本机构建架构；未做 Apple 公证，Android 使用调试签名。

使用与构建步骤见 [原生客户端说明](native/README.md)，协议见 [协议 v2](native/PROTOCOL.md)，验证范围见 [验证记录](native/VALIDATION.md)。

### UI 交互预览

`prototype/` 是已选第二套蓝白设计的交互预览，仅用于评审布局和流程，不会打包为正式应用。

已覆盖电脑面板、手机接收页、文字/图片/文件、历史记录、首次配对、取消配对、暂停同步、离线保留配对与自动重连演示。Mac/Windows 和 iPhone/Pixel 可切换预览。

预览使用模拟数据和本地界面状态；没有真实设备发现、网络传输、原生后台服务或持久配对存储。浏览器的复制与下载也不能替代四端原生能力验收。

运行预览：在 `prototype/` 执行 `npm ci` 与 `npm run dev`。构建检查：`npm run build`。

0.4 已补充图片预览、系统文件类型图标、图片与小文件自动接收后写入剪贴板，以及手机回到 CopyMore/系统分享发送到 Mac。大文件仍可按需下载；Android 后台读取限制与实测范围见 native/README.md 和 native/VALIDATION.md。
